# 2026-10-02 — 방해 금지 모드 알림

## 무엇을 확인했나
아이가 자는 밤에 부모 기기가 방해 금지(DND)여도 소음 알림이 오는지.
`cmd notification set_dnd priority` 로 방해 금지를 켜고, 감지기 옆에서 박수, 수신기 기록(`dumpsys notification` / `dumpsys vibrator_manager`)으로 판정.
시험 뒤 두 기기의 방해 금지·역할은 원래대로 되돌림.

## 수정 전
| 수신기 | 알림 | 진동 | 소리 |
|---|---|---|---|
| 워치 (방해 금지) | 통과 (`allowedAlarm`, 0.5초 만에 도착) | **2.5초, 알람 용도** | — |
| 폰 (방해 금지 + 진동 모드) | 통과 (`allowedAlarm`) | **1.1초 기본 진동 한 번** | 없음 |

- 알림은 `CATEGORY_ALARM` 이라 방해 금지를 통과했다
- 워치는 앱이 진동을 알람 용도(`USAGE_ALARM`)로 직접 울려서 문제없음
- 폰은 채널의 기본 진동(알림 용도)뿐이라 짧고 약했다. 밤에 놓치기 쉬움

## 첫 시도: 채널 소리를 알람 용도로 → 철회
- 채널 소리·진동을 `USAGE_ALARM` 으로 바꾸고 "알람 소리" 설정을 추가 → 진동은 알람 용도로 2.5초가 됐지만 **알람 소리는 실제로 안 울렸다**
  (시스템은 소리 낼 알림으로 기록 `mSoundNotificationKey`, 원인 미확인)
- 사용자 판단: **방해 금지에서는 진동만 나는 게 맞다** → 소리는 폰 설정을 따르게 하고 진동만 강하게

## 최종
- 진동: 앱이 직접 알람 용도로 길게 3번 (워치·폰 공통, `NoiseNotifications`)
- 소리: 채널의 일반 알림 소리 → 폰 소리 모드·방해 금지를 따름
- 채널 진동은 끔. 채널 진동 설정은 만든 뒤 바꿀 수 없어 새 채널 ID `noise`, 예전 `noise_alert` 는 삭제

| 수신기 | 진동 | 소리 |
|---|---|---|
| 워치 (방해 금지) | 2.6초, 알람 용도, 사용자 "3번 느낌" | — |
| 폰 (방해 금지 + 진동 모드) | 2.5초, 알람 용도, 사용자 "3번 잘 옴" | 없음 (의도) |

## 그 밖에
- 폰이 잠금 화면이면 adb 로 앱 버튼을 누를 수 없음(잠금 해제는 사람이) → 역할 전환이 한 번 건너뛰어짐
