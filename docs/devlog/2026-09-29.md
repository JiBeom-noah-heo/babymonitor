## 막힌 점 / 해결
- 셸 heredoc 으로 파일을 쓸 때 `\` 가 `\` 로 줄어들어 `settings.gradle.kts` 정규식(`com\.android.*`)이 `Illegal escape` 로 실패, `local.properties` 의 Windows 경로도 깨짐 → 정규식 수정, `sdk.dir` 은 슬래시(`C\:/Users/...`)로 작성.
- 최신 Android Studio 에 Wear+Phone 통합 템플릿이 없음 → 템플릿 대신 파일을 직접 구성.
- 워치 무선 디버깅 페어링 실패 (`adb pair` → `protocol fault (couldn't read status message)`)
  - `!` 로 실행하면 대화형 코드 입력이 안 됨 → `adb pair <IP:PORT> <코드>` 로 코드를 인자로 전달
  - 여전히 실패: PC 에서 ping·포트 접속 모두 불가. 원인은 **워치 IP 가 바뀌어 있었음** (.114 → .115). 페어링 화면의 최신 IP 로 재시도 후 성공
  - 페어링 후 `adb mdns services` 로 연결 포트가 자동 발견되어 별도 `adb connect` 없이 연결됨

# 2026-09-29 — Phase 1: 연결 확인 (PING / PONG)

브랜치: `phase/1-connection`

## 한 일
- `shared/Constants.Paths`: `/audio`, `/alert`, `/status`, `/control` 경로 상수
- `shared/ControlCommand`: `PING` / `START` / `STOP` / `SET_THRESHOLD:<dB>` 인코딩·디코딩 + JUnit 3개 (shared 테스트 총 4개 통과)
- 워치 `service/ControlReceiver` (WearableListenerService): `/control` 요청을 받아 PING → `PONG` 응답, 나머지는 `ERR:UNSUPPORTED`
- 워치 화면: 연결된 폰 이름(NodeClient), 받은 PING 횟수, 마지막 수신 시각
- 폰 `ui/HomeViewModel` + `HomeScreen`: 연결된 노드 목록, "PING 보내기", 결과 기록(응답 + RTT), 5초 타임아웃
- 결정 기록: `docs/decisions/002-control-request-response.md` (PONG 은 별도 경로 없이 `sendRequest` 응답으로)

## 막힌 점 / 해결
- 워치 무선 디버깅이 시간이 지나면 끊김 → 페어링은 유지되므로 `adb mdns services` 로 연결 포트를 찾아 `adb connect` 만 다시 하면 됨.
- Git Bash 에서 `adb shell uiautomator dump /sdcard/ui.xml` 경로가 `C:/Program Files/Git/sdcard/...` 로 바뀜 → `MSYS_NO_PATHCONV=1`.
- 워치가 절전 화면일 때 `screencap` 하면 흐리게 찍힘 → `input keyevent KEYCODE_WAKEUP` 후 캡처.

# 2026-09-29 — Phase 2: 워치 마이크 & 레벨 미터

브랜치: `phase/2-level-meter`

## 한 일
- `shared/Constants.Audio`: 16kHz, 100ms 윈도우(1600 샘플), 풀스케일 32768, 무음 하한 -96 dBFS, 표시 하한 -80 dBFS
- `shared/AudioLevel` (순수 Kotlin): RMS, RMS → dBFS(`20·log10(rms/32768)`), 레벨 바용 0..1 정규화
  - JUnit 7개: 무음, 풀스케일(±), 절반 진폭 -6.02 dB, 사인파 -3.01 dB / 1/10 진폭 -23 dB, 부분 버퍼, 범위 오류, 정규화 → shared 테스트 총 11개 통과
- 워치 `audio/AudioCapture`: AudioRecord 16kHz mono PCM16 → `Flow<ShortArray>` (100ms 프레임), 취소 시 stop/release
  - 버퍼: `max(getMinBufferSize × 2, 프레임 2개)` → 실측 minBuffer 1280 B, 사용 6400 B
  - 입력 소스 `VOICE_RECOGNITION`: AGC·노이즈 억제 없는 입력이라 레벨 비교가 일정함
- 워치 `audio/LevelMeter`: 프레임마다 dBFS 를 `StateFlow<Float>` 로 방출
- 워치 UI: `RECORD_AUDIO` 권한 요청(거부 시 재요청 안내), dB 숫자 + 레벨 바(100ms 애니메이션), 오류 표시
  - 측정은 화면이 보이는 동안만(`repeatOnLifecycle(STARTED)`) — 화면 꺼짐 대응은 Phase 3 `MonitorService`

## 결과
- 조용한 방 기준 약 **-55 dBFS**
- 박수·말소리에 따라 바와 숫자가 움직이는 것 확인. **Phase 2 완료 조건 충족.**
- 스크린샷: `docs/media/phase2-watch.png`

## 메모
- 권한 거부 후 재요청이 막히는 경우(두 번 거부) 설정 화면 이동 버튼은 아직 없음 → Phase 6 설정 화면에서 처리

# 2026-09-29 — Phase 3: 소음 알림

브랜치: `phase/3-noise-alert`

## 한 일
- `shared/NoiseDetector` (순수 Kotlin): 최근 1.5초 안에 -35 dBFS 이상이 합계 1초 이상이면 알림, 30초 쿨다운, 임계값 변경·리셋 지원 → JUnit 15개
- `shared/NoiseAlert`: `/alert` JSON `{"level":..,"ts":..,"kind":"NOISE"}` (kotlinx.serialization) → JUnit 4개. shared 테스트 총 30개 통과
- 워치 `service/MonitorService`: foreground(type=microphone) + PARTIAL WakeLock(12시간 상한), `START_NOT_STICKY`
  - 100ms 레벨 → NoiseDetector → `/alert` 를 연결된 모든 노드에 `sendMessage`
  - 1분마다 동작 로그 `alive: Ns, max=.. dBFS, alerts=N` (오디오 내용은 기록 안 함)
- 워치 `service/MonitorStatus`: 서비스 상태(실행 여부, dB, 알림 횟수, 전달 결과, 오류)를 UI 로 전달
- 워치 `audio/LevelMeter`: StateFlow 대신 `Flow<Float>` 로 단순화 (상태는 MonitorStatus 가 보관)
- 워치 UI: 모니터링 시작/정지, 레벨 바에 기준선 표시(넘으면 빨간색), "알림 N회 · 시각 전송됨/실패"
- 폰 `service/WearMessageReceiver`: `/alert` 수신 → `notification/NoiseNotifications` "소음 감지" 채널(IMPORTANCE_HIGH, 소리·진동) heads-up 알림
- 폰: 알림 권한(POST_NOTIFICATIONS) 요청, 받은 알림을 화면 기록에도 표시
- 결정 기록: `docs/decisions/003-noise-detection-rule.md`
