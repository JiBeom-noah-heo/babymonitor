# 007. 설정 동기화와 이벤트 기록

- 날짜: 2026-09-30
- 상태: 채택

## 배경
Phase 6 "설정 화면 (임계값 슬라이더, 쿨다운, 자동 스트리밍 여부)", "소음 이벤트 히스토리 (Room)".
감지 조건은 **감지기**에서 쓰이는데, 사람이 조작하는 화면은 대개 **수신기(부모 폰)** 쪽이다.

## 결정

### 1. 감지 설정은 감지기에 저장, 수신기는 원격으로 바꾼다
- `DetectionConfig` = 프리셋(집 안/차 안) + 사용자가 조정한 임계값(-70~-5 dBFS)·쿨다운(10초~10분).
  지속 조건(몇 초 중 몇 초)은 프리셋 고정.
- 감지기: `RoleStore` 에 JSON 저장 → `SensorEngine.setConfig` (모니터링 중이면 다음 프레임부터, 프리셋이 바뀌면 판정 새로 시작).
- 수신기 → 감지기: `/control` 에 명령 추가 (바뀐 항목만 보냄)
  | 명령 | 의미 |
  |---|---|
  | `SET_THRESHOLD:<dB>` | 임계값 (기존) |
  | `SET_COOLDOWN:<ms>` | 쿨다운 (신규) |
  | `SET_PRESET:<HOME\|CAR>` | 프리셋 + 그 기본값으로 (신규) |
- 감지기는 현재 설정을 `/status` 의 `config` 로 알린다 → 수신기 설정 화면이 표시. 감지기 앱을 한 번도 안 열었으면 "아직 모름".
- 원격으로 바뀐 설정도 감지기 쪽에 저장된다 (엔진 상태를 보고 `StatusHub` 가 저장).

### 2. 수신기 설정 (`ReceiverPrefs`, 기기별)
- **자동 듣기**: 알림이 오면 라이브 듣기 시작. 단 Android 는 백그라운드에서 재생 FGS 시작을 막으므로
  **앱이 화면에 있을 때만 바로** 시작하고, 아니면 알림의 **"듣기" 버튼**(사용자 조작 → FGS 허용)으로.
- **원격(클라우드) 라이브 듣기 허용**: 기본 꺼짐 (CLAUDE.md §8 "원격 스트리밍은 opt-in").
  꺼져 있고 연결이 원격이면 `StreamEnd.REMOTE_NOT_ALLOWED` (재시도 안 함). 알림은 이 설정과 무관.
- 워치가 수신기일 때도 같은 설정을 워치 화면 칩으로 바꾼다.

### 3. 이벤트 기록 (Room, android-common)
- `NoiseEvent(ts, level, role, preset, delivered, peerName)` — **소리는 저장하지 않음**.
- 감지기: 알림 전달 결과(보낸 수신기 수)가 정해지면 기록. 수신기: 리스너 서비스에서 받는 즉시 기록
  (앱이 막 깨어나 이벤트 흐름을 아직 구독하기 전이어도 빠지지 않게).
- 30일 보관, 최근 200건 표시. 짧은 오디오 클립(CLAUDE.md §1 "이후")은 범위 밖.

## 대안
- **설정을 수신기에 저장하고 감지기가 가져가기**: 감지기가 수신기 없이 동작할 때(연결 끊김) 설정을 잃음 → 기각.
- **`SET_CONFIG:<json>` 명령 하나**: 명령이 커지고, 기존 `SET_THRESHOLD` 와 중복 → 항목별 명령 유지.
- **자동 듣기를 백그라운드에서도 강행**: FGS 시작 제한으로 예외 → 알림 버튼으로 대체.
